# 우체국 소포 물량 예측 기반 배차 최적화

> 우정사업본부의 공개 소포 물량 데이터로 **노선별 일일 물량을 예측**하고,
> 예측 물량을 바탕으로 **직송할지, 가까운 거점으로 몰아 함께 보낼지**를 정해 운송비를 줄이는 프로젝트

[공모전/대회명] | 2026.06 ~ 2026.08 | [2인 팀]

**담당 역할**: 데이터 전처리, 예측 모델 설계 및 구현, 배차 최적화 방법 설계

<br>

## 결과

| 항목 | 결과 |
|---|---|
| 물량 예측 (테스트 기간 2026.06) | LSTM **WAPE 12.66%** (LightGBM 18.07%) |
| 배차 최적화 (예측 물량 기준) | 전부 직송 대비 운송비 **4.74% 절감** (약 1,446만 원) |
| 배차 최적화 (실제 물량 기준) | 전부 직송 대비 운송비 **5.08% 절감** (약 1,562만 원) |

- 예측 물량으로 배차를 계획했을 때의 절감률(4.74%)이 실제 물량을 알고 계획했을 때(5.08%)와 큰 차이가 없어, **예측 기반 사전 배차가 실제로 쓸 만하다**는 것을 확인했습니다.
- 운송비는 공개된 단가가 없어 가정치로 계산했습니다. 자세한 내용은 [비용 가정](#비용-가정)을 참고해 주세요.

## 1. 데이터 수집과 전처리

- 우정사업본부 홈페이지에 월별로 올라오는 소포 물량 파일(2025.01 ~ 2026.06)을 자동으로 내려받아 압축을 풀고 하나의 표로 합쳤습니다. (총 101,848건, 접수 지역 × 배달 지역 × 일자별 총중량)
- 시기마다 다른 지역명(예: `전라북도` → `전북특별자치도`)을 하나로 통일했습니다.
- **특성 생성**
  - 날짜: 연, 월, 일, 요일
  - 공휴일: 공휴일 여부, 다음 공휴일까지 남은 일수, 지난 공휴일부터 지난 일수, 공휴일 직전 3일·직후 2일 여부
  - 노선별 과거 물량: 1·2·7·14일 전 물량, 7일·14일 이동 평균과 표준편차, 전날 물량 대비 7일 평균 비율

<br>

## 2. 물량 예측

| 모델 | 구성 | 테스트 WAPE |
|---|---|:---:|
| LightGBM | 위 특성을 그대로 사용하는 회귀 모델 | 18.07% |
| **LSTM** | 접수·배달 지역을 임베딩으로 표현하고, 노선별 최근 14일 시퀀스로 다음 날 물량 예측 (Huber 손실) | **12.66%** |

LSTM이 더 좋아, 최종 예측에는 LSTM을 사용했습니다.

> 물량이 큰 노선의 오차가 전체 성능에 더 크게 반영되도록, 평가 지표로 **WAPE**(전체 실제 물량 대비 절대 오차 합의 비율)를 주로 사용했습니다.

## 3. 배차 최적화

같은 날 같은 지역으로 가는 물량이 여러 출발지에 흩어져 있을 때, 각자 보내는 것보다 **가까운 출발지로 먼저 모은 뒤 함께 보내는 것**이 싸질 수 있습니다. 작은 트럭을 여러개 쓰는데신 적은 수의 큰 트럭을 대신 쓸 수 있고, 큰 트럭은 kg당 운송비가 더 낮기 때문입니다.

### 트럭 조합 최적화 (OR-Tools CP-SAT)

정해진 물량과 거리에 대해, 실제 운용 중인 톤급(1 ~ 25톤, 10종)의 트럭을 **몇 대씩 조합해야 가장 싼지**를 정수계획법으로 계산합니다.
- 제약: 톤급별 적재량(90%까지만 적재) × 대수의 합 ≥ 물량
- 목적: 톤급별 (기본 출차비 + km당 비용 × 거리) × 대수의 합 최소화

### 직송 vs 몰아주기 (탐욕 알고리즘)

1. 처음에는 모든 출발지가 목적지로 각자 직송한다고 보고 비용을 계산합니다.
2. 남아 있는 모든 출발지 쌍 (i, j)에 대해 **"i와 j가 각자 직송"** 과 **"i의 물량을 j로 보낸 뒤 j에서 합쳐 직송 (+ 하역·분류비)"** 의 비용 차이를 계산합니다.
3. 가장 많이 절감되는 쌍을 골라 i의 물량을 j로 합치고, i를 목록에서 뺍니다.
4. 더 이상 절감되는 쌍이 없을 때까지 반복합니다.

어떤 순서로 어디에 몰아줬는지는 `merge_histories`에 날짜별·목적지별로 기록해, 결과를 경로 단위로 추적할 수 있게 했습니다.

### 계산 속도 개선

탐욕 알고리즘은 매 반복마다 모든 쌍을 다시 평가하기 때문에, 같은 (물량, 거리) 조합으로 트럭 최적화를 여러 번 호출합니다. OR-Tools는 모델을 만들고 푸는 비용 자체가 커서, 물량과 거리를 1kg·1km 단위로 반올림한 값을 키로 결과를 **캐싱**(`lru_cache`)해 반복 계산을 줄였습니다.

## 비용 가정

우정사업본부의 실제 운임, 하역비, 분류비 단가는 공개되어 있지 않아, 국토교통부 화물자동차 안전운송원가 고시 등을 참고한 **가정치**를 사용했습니다. (`dispatch.py`의 `COST_ASSUMPTIONS`)

| 항목 | 가정 |
|---|---|
| 톤급별 기본 출차비 | 1톤 30,000원 ~ 25톤 180,000원 |
| 톤급별 km당 비용 | 1톤 300원 ~ 25톤 1,800원 |
| 거점 경유 시 하역·분류비 | 1회당 25,000원 |
| 적재율 | 최대 90% |
| 거리 | 시·도 대표 좌표 사이의 직선거리 |

따라서 절감 금액 자체보다는 **어떤 조건에서 몰아주기가 유리해지는지**를 보여 주는 데 의미가 있으며, 실제 단가와 도로 거리를 적용하면 결과가 달라질 수 있습니다. 제주는 육로로 몰아줄 수 없어 분석에서 제외했습니다.

## 프로젝트 구조

```
├── data.py          # 데이터 다운로드, 압축 해제, 전처리, 특성 생성, 시계열 분할
├── lgbm.py          # LightGBM 학습·예측
├── lstm.py          # 지역 임베딩 + LSTM 학습·예측
├── models.py        # 평가 지표(MAE, RMSE, WAPE), 앙상블 가중치 탐색
├── dispatch.py      # 트럭 조합 최적화(CP-SAT), 직송 vs 몰아주기(탐욕 알고리즘)
├── integration.py   # 예측 결과 → 날짜·목적지별 배차 최적화 → 절감 요약
└── main.ipynb       # 전체 실행
```

## 기술 스택

Python, pandas, PyTorch(LSTM), LightGBM, scikit-learn, OR-Tools(CP-SAT)

## 실행 방법

```bash
pip install -r requirement
```
`main.ipynb`를 위에서부터 실행합니다. 데이터가 없으면 `data.download_pipeline()`의 주석을 풀어 내려받습니다.

## 한계와 개선 방향

- **실제 비용·거리 반영**: 공개 단가가 없어 가정치와 직선거리를 사용했습니다. 실제 단가를 확보하거나 지도 API의 도로 거리를 쓰면 결과의 신뢰도를 높일 수 있습니다.
- **예측 오차의 영향**: 예측이 실제보다 적으면 트럭이 부족해질 수 있습니다. 예측오차를 고려해 여유 용량을 정하는 방향으로 개선할 수 있습니다.
